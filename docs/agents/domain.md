# Domain Docs

## Before exploring

Read GLOSSARY.md at the repo root and any relevant decisions in docs/adr/.

If these do not exist, proceed silently. The domain-modeling skill
creates them when terms or decisions are resolved.

## Layout

This repo uses a single context:

- GLOSSARY.md: shared domain vocabulary
- docs/adr/: architectural decision records

## Vocabulary and decisions

Use glossary terms in issues, proposals, hypotheses, and tests.
If a needed concept is missing, note the gap for domain-modeling.

Explicitly flag proposals that contradict an existing ADR, identifying
the decision and explaining why it should be reconsidered.
